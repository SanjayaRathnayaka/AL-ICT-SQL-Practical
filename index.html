25. SQL Join Queries (වගු සංයුක්ත කිරීම)[cite: 5]

දත්ත සමුදායක වගු කිහිපයක දත්ත එකට සම්බන්ධ කර එකවර බලා ගැනීමට SQL Join භාවිතා කරයි[cite: 5]. ඒවා ප්‍රධාන ආකාර 4 කි[cite: 5].

1. INNER JOIN

වගු දෙකක දත්ත අතරින් වගු දෙකටම පොදු (Matching) දත්ත පමණක් ලබාගැනීමට මෙම ක්‍රමය යොදා ගනී[cite: 5].

SELECT student.Name, marks.Subject, marks.Score FROM student INNER JOIN marks ON student.StudentID = marks.StudentID;

2. LEFT JOIN

වම්පස වගුවේ සියලු දත්ත සමඟ දකුණු පස වගුවේ ගැළපෙන දත්ත පමණක් ලබා ගැනීමට භාවිතා කරයි[cite: 6].

SELECT student.Name, marks.Subject FROM student LEFT JOIN marks ON student.StudentID = marks.StudentID;

3. RIGHT JOIN

දකුණු පස වගුවේ සියලු දත්ත සමඟ වම් පස වගුවේ ගැළපෙන දත්ත පමණක් ලබා ගැනීමට භාවිතා කරයි[cite: 6, 7].

SELECT student.Name, marks.Subject FROM student RIGHT JOIN marks ON student.StudentID = marks.StudentID;

4. FULL OUTER JOIN / FULL JOIN

LEFT JOIN සහ RIGHT JOIN යන අවස්ථා දෙකෙහිම සංයෝගයෙන් ප්‍රතිදානය පෙන්වයි[cite: 7].

SELECT student.Name, marks.Subject FROM student FULL JOIN marks ON student.StudentID = marks.StudentID;

දත්ත සමුදාය ප්‍රමතකරණය (Database Normalization)[cite: 7]

දත්ත සමුදායක ගබඩා වන දත්තවල විවිධ විශමතා / විපරිතතා (Anomalies) අවම කිරීම සඳහා ප්‍රමතකරණය භාවිතා කරයි[cite: 7].

1. දත්ත සමුදා විපරිතතා (Anomalies):[cite: 7]
  • දත්ත අනුපිටපත්වීම (Data Redundancy): එකම දත්තය නැවත නැවත පිටපත් වීම නිසා අනවශ්‍ය ඉඩකඩ වැයවීම සහ නඩත්තුව අපහසු වීම[cite: 7, 8].
  • ආදාන විපරිතතා (Input Anomalies): වෙනත් දත්ත ලැබෙන තෙක් දැනට පවතින දත්ත ආදානය කිරීම අපහසු වීම[cite: 8].
  • මකා දැමීමේ විපරිතතා (Delete Anomalies): දත්තයක් මකා දැමීමේදී ඊට අමතරව වෙනත් වැදගත් දත්තද මැකී යාම[cite: 8, 9].
  • යාවත්කාලීන කිරීමේ විපරිතතා (Update Anomalies): එකම දත්තය ස්ථාන ගණනාවක පවතින විට සියලු ස්ථානවල එකවර යාවත්කාලීන කිරීමට අපහසු වීම[cite: 9].
2. පරායක්තතාවන් සහ උපලක්ෂණ (Dependencies):[cite: 9, 10, 11]
  • කාර්යබද්ධ පරායක්තතාවය (Functional Dependency): එක් උපලක්ෂණයක් මඟින් වගුවේ වෙනත් උපලක්ෂණයක් අනන්‍යව හඳුනාගත හැකි වීම[cite: 9].
  • පූර්ණ පරායක්තතාවය (Full Dependency): සෑම උපලක්ෂණයක්ම ප්‍රාථමික යතුර මත පමණක් රඳා පැවතීම[cite: 10].
  • ආංශික පරායක්තතාවය (Partial Dependency): සංයුක්ත ප්‍රාථමික යතුරක (Composite Primary Key) එක් කොටසක් මත ප්‍රාථමික නොවන ක්ෂේත්‍රයක් රඳා පැවතීම[cite: 10].
  • සංක්‍රාන්ති පරායක්තතාවය (Transitive Dependency): ප්‍රාථමික යතුරු නොවන ක්ෂේත්‍ර දෙකක් අතර එකිනෙක රඳා පැවතීම[cite: 11].
  • බහු අගයන් සහිත උපලක්ෂණ (Multivalued Attributes): එක් උපලක්ෂණයක් සඳහා එකකට වඩා වැඩි අගයන් ප්‍රමාණයක් ඇතුළත් වී තිබීම (උදා: දුරකථන අංක දෙකක් එකම තීරුවක යෙදීම)[cite: 11].
3. ප්‍රමත මට්ටම් (Levels of Normalization):[cite: 11]
0NF (ශුන්‍ය ප්‍රමත අවස්ථාව / Unnormalized):[cite: 11, 12]

සියලුම දත්ත එකම පැතලි වගුවක (Flat File) පැවතීම[cite: 11, 12]. බහු අගයන් සහිත උපලක්ෂණ සහ විපරිතතා පවතී[cite: 11, 12].

1NF (පළමු ප්‍රමත අවස්ථාව):[cite: 12, 13]

වගුවක සෑම තීරුවකටම තනි පරමාණුක අගයක් (Atomic Value) පමණක් ඇතුළත් විය යුතුය[cite: 12, 13]. බහු අගයන් සහිත උපලක්ෂණ වෙනම වගුවකට වෙන් කර ප්‍රාථමික/ආගන්තුක යතුරු මඟින් සම්බන්ධ කළ යුතුය[cite: 13].

2NF (දෙවන ප්‍රමත අවස්ථාව):[cite: 13, 14]

වගුව 1NF හි පැවතිය යුතු අතර, සියලුම ආංශික පරායක්තතාවන් (Partial Dependencies) ඉවත් කර තිබිය යුතුය[cite: 13, 14]. සංයුක්ත ප්‍රාථමික යතුරක කොටසක් මත රඳාපවතින ක්ෂේත්‍ර වෙනම වගුවකට මාරු කළ යුතුය[cite: 14].

3NF (තෙවන ප්‍රමත අවස්ථාව):[cite: 14, 15]

වගුව 2NF හි පැවතිය යුතු අතර, සියලුම සංක්‍රාන්තික පරායක්තතාවන් (Transitive Dependencies) ඉවත් කර තිබිය යුතුය[cite: 14, 15]. ප්‍රාථමික යතුරු නොවන ක්ෂේත්‍ර අතර පවතින අන්‍යෝන්‍ය රඳාපැවතීම් වෙනම වගු ලෙස සකස් කළ යුතුය[cite: 14, 15].
